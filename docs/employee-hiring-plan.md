# 雇佣员工与自选团队：后续需求

记录于 2026-11-04，来自用户本轮要求。状态：待后续实现，尚未新增导航、岗位或雇佣接口。

## 使用目标

未来对外开放时，用户可在左侧“雇佣员工”中按自己的需求选择岗位和员工，组成团队；不强制所有用户拥有同一套员工。

首版建议流程：浏览岗位 → 查看角色、职责和可用技能 → 了解所需服务及费用 → 确认雇佣 → 自动安排工位 → 秘书能识别新员工并派发对应任务。仅有角色卡片不算完成雇佣功能。

## 角色与岗位分开管理

- 角色是一套外观与身份设定；岗位是职责、技能和执行范围。高清对话形象与办公室动作使用同一个角色组，不能串人。
- 岗位模板不直接充当在职员工；确认雇佣后，才为当前工作空间创建独立员工实例。
- 员工技能、工作记忆、任务记录分别保存；不能因为雇了同一个模板就共享其他工作空间的资料。
- 原有员工、历史成果和任务归属应保留；停用员工前处理未完成任务，支持后续重新启用。
- 秘书拆分任务时只安排当前已雇佣、具备能力的员工；缺岗位时给出明确说明或雇佣建议，不虚构执行能力。

## 建议实现顺序与验收

1. 动态团队基础：解除固定 9 人/9 工位限制，明确可雇用上限；支持多个同岗位员工的独立编号。
2. 左侧“雇佣员工”：岗位分类、搜索、角色预览、职责、默认技能与服务依赖说明；真实保存到当前工作空间。
3. 雇佣后的闭环：办公室出现对应人物，员工档案可管理独立技能，秘书可分配任务，结果正确归属该员工。
4. 停用/重新启用、团队组合模板，以及按团队显示预计使用成本。确认费用和权限前不自动开通外部付费服务。

验收重点：切换企业不串团队；刷新与重启后雇佣结果保留；同岗位两人不会共用记忆；缺服务明确提示；取消雇佣不留半个员工；停用不丢历史任务；新角色的坐姿、行走和工位遮挡实际验证。
