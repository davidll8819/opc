# 模型连接超时排查与修复

日期：2026-10-24（北京时间）。本轮只修模型连接与故障说明，不改办公室动画、员工技能绑定、保存的模型配置和历史费用。

## 发现及证据边界

1. 两次真实调研请求分别在约10.5秒后失败，旧代码只显示“结果未知”，没有留下底层错误分类；无法据此还原那两次调用的确切网络原因或服务商收费状态。
2. 此前无凭据连通测试真实出现 `UND_ERR_CONNECT_TIMEOUT`（建立连接超时）。之后网页、模型列表和3个地址的加密连接又均成功，说明单次连通成功不能代表长期稳定。
3. 本轮使用保存的调研模型做一次“只回复OK”测试，8079毫秒成功返回，HTTP200、finish_reason=stop。说明当时保存的密钥和模型可以使用，不需要先轮换密钥或更换模型。
4. 检查本机Node运行时实际源码，连接器默认 `timeout = timeout == null ? 1e4 : timeout`，即10秒。原应用仅设置300秒的整体取消信号，没有显式设置连接建立的超时。这是已确认的应用容错缺口，与历史约10.5秒失败高度吻合，但不能把它当作网络瞬断具体原因的完整证明。
5. 官方接口也区分整体取消与连接超时：[Node fetch自定义dispatcher](https://nodejs.org/api/globals.html#custom-dispatcher)、[Undici客户端连接参数](https://github.com/nodejs/undici/blob/main/docs/docs/api/Client.md)。实现另据安装版本及本机运行时核对。

## 最小修复

- `apps/api/src/operations/model-transport.mjs`：仅用于固定模型服务，连接窗口设为30秒，多地址自动选择；保留原调用的整体取消信号，禁止跳转到其他地址，不启用生成重试代理。
- `apps/api/src/app.mjs`：生产应用共享这个专用连接池，关闭应用时释放；测试提供的替身不受影响。不修改全局网络配置，不关闭证书验证，不固定服务商IP。
- `apps/api/src/operations/model-errors.mjs`与`gateway.mjs`：对域名解析、连接超时、回复等待超时、连接中断和证书校验失败给出不同提示。仅允许固定分类文案，不输出原始错误、请求正文、请求头或凭据。未知结果仍保留预占额度，不自动重试。
- 只增加`undici@7.30.1`这一依赖，既有依赖版本改动数为0；没有批量升级整棵依赖树。

连接窗口延长能容忍较慢的连接，不保证服务商或本机网络永远正常。发生真实断网、服务商故障或超过30秒的建连延迟仍会明确失败。
