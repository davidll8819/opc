# 远程访问方案（仅方案，未启用）

日期：2026-10-21。本轮没有开启远程登录、安装VPN、放开端口、申请域名或部署公网入口。先把功能做完整，远程方案可随后单独验收。

## 推荐第一步：只让你自己的另一台电脑使用

建议先用私有网络连接两台电脑，再通过SSH加密通道访问。私有网络相当于只允许获准设备加入的内部网络；SSH通道把另一台电脑的本地入口转接到这台Mac，不必公开模型代理或数据库。

可考虑Tailscale建立私有设备网络，再使用macOS的OpenSSH。它需要两台设备安装和账户授权，实施前再确认账户和可用网络；本轮未登录或开通。[Tailscale官方入门](https://tailscale.com/docs/how-to/quickstart)。OpenSSH本身支持加密端口转发。[OpenSSH官方手册](https://man.openbsd.org/ssh#L)。

针对当前项目的设计建议（尚未实测）：

- 只给你自己的设备访问权限，使用独立SSH密钥，不共享管理员密码。
- 远端浏览器仍打开 `http://localhost:3000`，转发到这台Mac的 `127.0.0.1:3000`，保留当前本地认证的来源要求。
- 视频目前使用 `127.0.0.1:19000` 链接，所以还要把远端同名本地端口转发到Mac的19000，才能观看现有视频。这只适合你自己的受信任设备；当前匿名媒体桶不能当成团队权限方案。
- 模型代理3456、视频内部服务3302/3310、数据库和缓存端口不开放给远端浏览器。
- Mac必须保持联网和服务运行，休眠后无法稳定提供服务。远端3000/19000不能被其他程序占用。

完成标准：另一台电脑能登录、对话、看任务和视频；未授权设备进不来；断开通道后入口不可达；原Mac使用不受影响。浏览器权限、跨域和来源校验仍需实机验收，不仅检查端口能否连接。

## 第二步：团队成员稳定访问

当需要多人使用、手机访问、固定网址时，再做独立预发布环境：

1. 正式域名和HTTPS（加密网页连接），使用已有正式身份方案，验收邀请、角色、退出、找回密码与会话失效。
2. 统一入口负责页面与接口，内部视频服务仍留在私有网络；不把开发登录直接暴露到公网。
3. 媒体通过检查登录权限的下载接口或短时授权链接访问；去掉当前公开读桶策略，旧视频地址要有迁移办法。
4. 部署数据库、MongoDB、文件存储、进程守护、日志与备份；恢复演练通过后再考虑切换入口。
5. 测试跨企业隔离、连续任务、取消/重试、媒体下载和模型费用上限，再给出人数容量承诺。

目前不要购买规格或承诺并发人数：现有测试还不能确定真实长任务的资源需求。先记录少量真实用户的任务耗时、排队和媒体体积，再选服务器。

## 与功能修复的顺序

建议先完善本地核心流程，再实施远程入口：

1. 视频交付闭环：复用现有底片，加中文字幕/提示、裁剪拼接、音量处理；明确“已生成、待验收、可交付”。
2. 成果页：先给成品和结论，长执行记录折叠，让用户容易找到下载与下一步。
3. 文件管理：容量提示、删除/回收、引用保护，避免空间满后无处清理。
4. 自检体验：保留最近自检时间和结果，补清晰错误和中英文提示。
5. 按实际需要接程序执行环境、平台发布；每个能力分别验收，不为凑齐功能而启用未配置模块。

办公室动画和员工独立技能绑定继续保持。本文件是排期建议，不代表已经实施这些功能。
