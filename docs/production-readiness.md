# 第五批：邀请测试前的本地准备与操作说明

本轮只做本机可验证的启动保护、权限检查和故障演练。**第五批尚未全部完成，也没有发布网站或邀请外部用户。** 办公室动画、员工技能绑定、模型配置和真实业务数据保持不变。

## 已补上的保护

1. 正式环境在连接数据库、监听端口之前，检查 HTTPS、正式登录、源站验证、企业加密主密钥、数据库证书、缓存加密连接和媒体 HTTPS 配置。缺项就拒绝启动，错误只列检查编号，不打印配置值。
2. 正式环境连接数据库后，拒绝使用管理员或可以绕过资料权限的数据库账号。数据库里的权限隔离称为 RLS，本轮在真实 PostgreSQL 中以受限角色验证了读取路径。
3. 就绪检查最多等待约 2.5 秒，失败返回 503（表示暂时无法服务），不再无限等待；并发检查合并执行，结果缓存 1 秒。一个探测卡住时不会不断新增同类后台探测。恢复后重新检查。
4. 新增可重复执行的隔离演练：新数据库、独立 Redis（保存登录会话的缓存服务）、临时 HTTP 端口；结束后移除测试资源。不会调用收费模型、生成视频或发布。

这套检查不改变本机开发模式；不会帮你重写 `.env`、主密钥或模型配置。证书检查仅验证可读取、可解析的 CA 证书，真实服务器 TLS 握手仍需在预发布环境验收。代码同时禁止在 `DATABASE_URL` 中用 SSL 参数覆盖统一证书校验：当前安装的 PostgreSQL 驱动会优先采用连接串里的参数，单检查证书文件不足以保证实际连接设置正确。

## 怎么检查

在项目根目录执行，使用 Node 24：

```sh
PATH="$PWD/.local/bin:$PATH" node --env-file=.env scripts/check-production.mjs
```

退出码 0 表示本次配置检查通过；1 表示尚不满足正式启动条件。它只读取配置和相关文件，不连接云端、不申请资源、不修改配置。**当前 `.env` 是本机配置，返回 1 是预期结果，不能为了让它变绿就更换现有密钥。** 对未来独立预发布环境，应将 `--env-file` 指向该环境自己安全保存的配置文件。

正式环境通过 `apps/api/src/server.mjs` 启动（现有 Docker 镜像也是此入口）时，会自动执行相同检查，并核对实际数据库角色。`APP_ORIGIN` 和登录域名填写完整 HTTPS 源地址，不带末尾斜杠、路径、参数或账号密码。配置通过不代表登录账号真的可用、媒体存储已私有化或商业许可已核验。

本地专项测试：

```sh
PATH="$PWD/.local/bin:$PATH" node --test tests/production-readiness.test.mjs
PATH="$PWD/.local/bin:$PATH" node scripts/verify-production-readiness.mjs
PATH="$PWD/.local/bin:$PATH" npm test
```

第二个命令需要当前本机 PostgreSQL 管理凭据、现有 `office_app` 角色，以及 `.local/services/bin/redis-server`；它限制连接本机 PostgreSQL。临时数据库名称以 `readiness_test_` 开头，测试 Redis 只有私有 Unix socket，没有对外 TCP 端口。正式业务数据库不参与写入，现有 Redis 不会被暂停或清空。Redis 暂停以及连接池占满演练只针对这次启动的测试实例和连接池。

## 故障时先看哪里

```sh
curl --max-time 5 --fail http://localhost:3000/health/live
curl --max-time 5 --fail http://localhost:3000/health/ready
PATH="$PWD/.local/bin:$PATH" node scripts/service-watchdog.mjs status
```

- `live` 返回 200：主程序能够回答请求；不代表模型、视频、数据库全部正常。
- `ready` 返回 200：本次数据库与缓存探测通过；最多缓存 1 秒，仍不代表上游模型或视频平台可用。
- `live` 为 200、`ready` 为 503：先检查数据库/缓存或连接池占用；不要重新提交付费任务来“测一下”。
- `live` 也失败：先检查主进程。本机守护只恢复缺失服务，不应自动重跑付费生成。
- 模型请求显示“结果未知”：先查看原任务和费用记录，核对上游结果后再决定恢复；不按普通网络错误直接重试。

新健康接口不返回数据库地址、账号、异常原文、连接串或服务商凭据。原有日志脱敏/轮转规则保留。本轮没有新增邮件/微信报警，也没有改变守护的重试策略或全业务请求超时。

### 小规模读取测试的边界

每档 30 次请求，交替读取资料列表与工作知识列表，真实 HTTP/数据库/缓存；仅临时小数据集。

| 同时请求数 | 成功数 | 全档耗时 | 95% 请求在此时间内返回 |
| --- | --- | --- | --- |
| 5 | 30/30 | 38 ms | 20 ms |
| 10 | 30/30 | 22 ms | 19 ms |
| 20 | 30/30 | 11 ms | 9 ms |

后面的档位已有连接和缓存预热，样本很小，所以更高并发更快并不代表服务器容量更高。这些数字不能推算可售用户数，更不能代表多用户同时调研、视频生成、下载大文件的性能。尚未做持续压力、目标云机型、真实网络和付费任务混合负载测试。
