# 第一批安全修复：内部凭据与日志

本次不改变保存的供应商Key、模型型号、员工技能或业务数据。

## 已生效

- 启动器为每个进程生成32字节随机代理密码，通过内部环境变量 OFFICE_CCR_API_KEY 传给模型代理和执行器。手动单独启动服务时必须提供至少32字符、无空白的密码，否则拒绝启动；不回退固定密码。
- 代理只监听本机，只允许经过认证的 POST /v1/messages 和 POST /v1/messages/count_tokens。管理配置、日志、预设、UI接口一律关闭，当前密码也不能读取。
- CCR自行写入的原始日志已关闭。两个视频应用及其子进程通过启动前加载的统一过滤器写安全日志。敏感行整体替换，不输出密钥片段。
- 新日志目录 `.local/production-runtime/logs/secure/` 权限0700；文件0600。按日期和5MB大小轮转，保留14天，在产生下一条日志时检查到期文件。旧日志不在自动清理范围内。
- 已得到用户确认，4个旧日志敏感行已脱敏，文件及其他记录保留。

## 凭据轮换已完成（2026-10-21，用户明确授权后）

1. **代理内部密码：**启动时随机生成，旧固定密码已失效。
2. **企业内部模型网关凭据：**已随机更换运行注册表中该企业的 `bridgeSecret`，主站和视频服务已重启。旧网关凭据返回403；旧桥接签名在两个视频服务均返回403。
3. **JWT签名凭据：**已随机更换同一企业的 `jwtSecret`。用旧签名凭据产生的访问令牌无法读取任务/账户，新令牌读取成功。此上游接口用HTTP200包装业务认证错误，验证同时检查业务错误码，没有把HTTP200误判为登录成功。
4. **模型和视频验证：**代理的真实简短模型请求返回200并收到文字；视频server/AI桥接均就绪；现有视频分段读取返回206、读到128字节。没有重新生成视频或创建业务任务。

供应商Key、模型型号、员工技能、其余运行注册表字段均保持原内容。旧注册表恢复副本仅保存在项目外的私有密钥备份目录，权限0600；日常操作不应恢复它，否则会重新启用已经撤销的凭据。以后从旧备份恢复系统时，也必须保留新凭据或再次轮换。

目前无需你再手动更换这两项内部凭据。本次没有证据证明4YI供应商Key被此前代理日志暴露，未更换供应商Key。

原始来源是 `.local/operations-runtimes.json`。`.local/operations/<企业ID>/server.yaml` 和 `ai.yaml` 使用环境变量引用；先核对引用仍在，不要把新密钥硬编码进去。`.claude-session/.claude-code-router/config.json` 由服务启动自动生成，不应手工编辑。供应商配置在加密数据库中，本轮未修改，也不需要为修代理密码而改模型型号。

## 检查命令

在项目根目录，用项目内Node执行：

```sh
PATH="$PWD/.local/bin:$PATH" node scripts/verify-router-security.mjs
PATH="$PWD/.local/bin:$PATH" node --test tests/runtime-log-security.test.mjs tests/operations-launch.test.mjs
```

第一条会发一次简短模型请求，产生少量模型用量，但不创建业务任务。只输出状态和是否通过，不打印密钥或模型正文。

`node scripts/restart-operations-security.mjs` 只在没有正在执行的视频任务时重启两个应用，不重新导出模型配置、不重启数据库。进行重启期间不要派发新任务。若失败，检查安全日志；不要以原始控制台直连文件的方式绕过过滤器。
