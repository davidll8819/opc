# 当前 Mac 系统怎么备份、怎么恢复

这套脚本对应当前原生 Mac 服务，使用项目自带的数据库工具，不依赖 Docker。它不会更改员工、模型或业务记录。执行期间请暂停派发新任务、上传素材和修改设置；脚本会拒绝在已有视频生成任务运行时备份。各数据库各自使用一致快照，但不同服务之间不是一个共同事务，所以保持业务空闲仍很重要。

## 备份什么，放在哪里

- `~/Wishtaday-Backups/<时间编号>/`：PostgreSQL数据库、MongoDB全部集合及索引、RustFS媒体原文件、核对清单。PostgreSQL使用同一个只读快照导出并计数；MongoDB使用只读快照读取，保留原始BSON数据类型。
- `~/Wishtaday-Backup-Keys/<同一时间编号>/`：`.local/operations-config.key`、`.env`、本地运行注册表、基础服务凭据、生成的运行配置、完整代理会话（排除日志与PID）。代理会话可能也有账号信息，因此一起放在更敏感的密钥目录。
- 两处目录都在项目之外，目录权限0700、文件0600，只有当前系统用户可读写。脚本不输出密钥，不自动删除旧备份。
- **为什么分开：**数据库保存了加密的模型配置，而主密钥能解开它。分开保管可避免只拿到数据库备份的人同时拿到钥匙。现在两个目录仍在同一块硬盘，不能抵御整机丢失或硬盘损坏；请把数据副本和密钥副本分别放到受保护的外置介质/位置。这里的目录权限不等于整个备份已加密。
- 不复制正在写入的数据库原始文件；媒体通过文件服务读取，而不是直接拷贝RustFS内部数据块。Redis登录缓存不作为恢复依据，恢复后允许重新登录。

## 怎么备份

打开终端，在项目根目录执行：

```sh
cd /Users/david/Documents/ChatGPT/WishTaday/ops
PATH="$PWD/.local/bin:$PATH" node scripts/backup-system.mjs
```

输出中 `status: complete` 表示完成，同时给出两个目录位置。成功目录包含 `COMPLETE` 文件；没有这个文件的目录是未完成备份，不能拿来恢复。

可指定项目之外的两个独立位置：

```sh
PATH="$PWD/.local/bin:$PATH" node scripts/backup-system.mjs /你的数据备份目录 /你的密钥备份目录
```

脚本读取本机已有的数据库管理员密码来做完整备份，不改变应用账号权限。普通应用账号有数据隔离限制，不能拿它来做全库备份。服务器或账号方案改变后，需要重新验收脚本，不能直接当作通用云备份工具。

## 怎么验证恢复

下面这条是**安全恢复演练**，不覆盖正在用的系统。把两个路径替换为同一次备份输出的目录：

```sh
PATH="$PWD/.local/bin:$PATH" node scripts/restore-backup.mjs \
  /Users/david/Wishtaday-Backups/备份时间编号 \
  /Users/david/Wishtaday-Backup-Keys/备份时间编号
```

脚本会：

1. 先核对备份是否完整，以及两个目录是否配套。
2. 在本机PostgreSQL新建随机命名的临时数据库，恢复后比较每张表的记录数。
3. 在新的系统临时目录启动独立MongoDB，恢复集合、索引和记录，逐集合比较数量。
4. 启动另一个临时RustFS，恢复媒体，再读回来比较SHA256——它是文件内容的校验值，内容变了就会不一致。
5. 恢复代理会话和私有配置到临时目录，逐文件比较校验值。
6. 输出 `status: verified`。关闭临时MongoDB/RustFS，删除**本次随机创建**的临时PostgreSQL数据库，保留临时文件和 `RESTORE_VERIFICATION.json` 供检查。正式数据库和素材桶从未作为恢复目标。

可增加第四个参数，指定一个**尚不存在**的新目录；已有目录会被拒绝。临时目录里仍有敏感数据，不要上传或分享整个目录。系统可能自动清理临时目录，长期保留的备份仍在项目外的两个目录中。

## 真正换机器或灾难恢复

先在新机器安装同版本项目和基础服务，保留原机器数据，复制两个备份目录，完成上述恢复演练。演练通过后，再由维护者在新环境恢复正式数据库、应用用户权限、素材桶和配置，核对域名/端口/路径，轮换内部凭据，最后切换访问入口。

当前脚本刻意只提供“恢复到全新隔离环境”，不提供一键覆盖现有生产库，以免误操作。生产切换、账号权限重建和新服务器部署不属于本次恢复演练的已验证范围。

## 多久备份一次

- 日常使用：每天结束工作后备份一次。
- 升级、迁移、批量导入或改配置前：额外备份一次。
- 建议保留最近14天每日备份，再保留最近3个月的每周备份；删除时成对核对编号，重要里程碑另行保留。
- 每月至少做一次恢复演练；重要版本升级后也做一次。

本轮没有安装定时任务；目前需手动执行，避免未经确认改变电脑的后台计划。
