# 工作知识升级：界面、真实调用与模板导入

2026-10-26。已在本地主应用启用。办公室动画、技能绑定和模型配置未改；未替用户导入假资料或重跑真实任务。

## 怎么使用

从左侧「工作知识」进入，分为知识库、长期记忆、流程模板和任务通知。

| 入口 | 放什么 | 实际怎么用 |
| --- | --- | --- |
| 知识库 | 产品资料、客户背景、品牌规则 | 秘书、新任务与普通员工对话按项目和问题选择启用内容；任务保留当时版本 |
| 长期记忆 | 明确确认的表达习惯、长期要求 | 在适用项目内作为背景要求，支持更正、停用和删除；当前明确要求优先 |
| 流程模板 | 有负责人、步骤要求、前后依赖的重复工作 | 填本次参数 → 预览 → 创建待确认分工 → 秘书确认派发 → 按依赖执行 |

页面提供名称/内容搜索、启用状态和项目筛选。电脑端列表与编辑区分开，手机端编辑区优先显示。每条资料能看到类型、版本、项目和是否参与后续调用。个人数据仍仅本人在当前企业内可见，不是全员共享知识库。

### 导入知识

1. 点击「导入文字文件」，填写适用项目；留空表示全项目可用。
2. 选择 UTF-8 编码 TXT 或 Markdown，最多 32000 字、256 KB。长文按每条不超过 4000 字分段，预览能展开全部分段。
3. 核对后点击「确认导入知识」，才保存并启用。完全相同的内容、名称、来源、项目和启用状态会复用现有条目；并发重复导入也不会重复创建。
4. 库中仍有 200 条容量上限；超过容量整批拒绝，不会只保存一半。
5. 「检查本次会用到哪些知识」填写项目和问题，查看检索结果。该预查不调用付费模型。

PDF、Word 目前不能在这个新入口直接导入，需要先在资料室解析，核对文字后复制到知识条目，或另存为 TXT/Markdown。扫描识别、表格结构和直接挂接原文档版本链还未打通到工作知识。

### 员工实际调用

普通员工对话新增「工作知识范围」，可填知识项目名称（精确匹配）。发送时读取适用资料和记忆；回复下方显示「本次带入的工作知识」，包含名称、版本、项目和来源。这证明内容实际进入模型请求，不代表模型一定采用全部内容或保证答案正确。

秘书和模板新建任务的原有知识快照链路仍保留，后续员工执行会拿到创建时的快照。修改或停用条目不追溯改写已创建任务；新的普通对话不再选入停用内容，但旧对话已经讨论过的内容仍存在历史消息里。

文档比对、正式档案问答与项目代码执行仍使用各自的来源机制，不混入这套新知识。外部服务自行发起的独立工作也未统一接入；秘书任务链通过任务要求和前序成果交接。

检索仍是关键词加人工近义词，不是语义检索（按意思而非字面匹配）。每轮最多 12 条、正文共 12000 字，超出部分不会全部送给模型。导入长文不等于模型每次读完全文。

### 什么模板上传后能用

支持 **Wishtaday v1 JSON**。JSON 是有固定字段的文本格式，用来把步骤准确交给程序。

- 页面「下载格式示例」提供可用样例；本地样例：[wishtaday-workflow-v1.json](templates/wishtaday-workflow-v1.json)。
- 必须包含 `format: wishtaday.workflow`、`version: 1`、名称、需求单和 1–10 个步骤。
- 每步包含名称、系统内员工编号、步骤要求、依赖编号。依赖从 0 开始：`[0]` 表示等待第 1 步。
- 每次变化的值写成 `{{项目}}`、`{{目标}}` 等参数，最多 12 个；只允许文字、数字和下划线组成参数名。
- 系统拒绝未知负责人、循环等待、不存在的步骤、错误参数、额外脚本/接口字段、未知格式版本。
- 已有模板支持导出同一格式，再上传复用。导出前请自行核对模板正文是否含客户私有资料。
- 普通 Word/PDF 流程说明以及 n8n、Coze 等其他平台文件目前不能原样执行，需要先转换为本规范。

上传校验和保存模板不启动任务，也不扣模型额度。创建分工仍是草稿，必须确认派发；对外发布继续保留人工确认。

## 后续最有价值的完善

1. 用真实产品说明、品牌规则和一个日常流程做小规模验收；目前真实知识库仍为空。
2. 直接选取资料室 PDF/Word 解析结果作为知识来源，保留原件链接、版本及失效提醒。
3. 建立一组典型问题与正确资料的对照，再决定是否增加语义检索；避免只增加算法却无法判断效果。
4. 需要团队协作时，再增加个人/项目/企业共享范围和更细权限；当前仍是个人知识。
